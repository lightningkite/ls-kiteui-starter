HeroScript V1 — click-through wireframe

Discussion artifact for Jon. Embodies the basket-first Order shape priced in the estimate. The currently built Kotlin app composes one prescription per order; the proposed shape (estimate § Major forks) is what this mockup demonstrates.

Reading the wireframe:
  • Prescription is durable. It's the clinical authorization (patient + product + sig + endsAt) and exists independently of any fulfillment.
  • Order is a basket of fulfillments. One ship-to, one pharmacy, N PrescriptionOrder lines (each against an existing or just-written Prescription), one dispatch.
  • ID.me fires when signing a new Prescription, not at order submit. Refill orders against existing Rxs reuse the prior approval.
  • Sig templates are a static client-side catalog that populates a freehand instructions textarea.
  • Pharmacy licensing filters on ship-to state. Pharmacy eligibility = intersection of all basket products ∩ licensed states.

Alternative model shapes

The order model has a real fork. Two axes (durable Prescription? separate dispatch entity?) generate three viable shapes. This mockup walks Combined Basket; the alternative is mocked too.

  • Combined Basket (this mockup). One screen: patient → lines → pharmacy → submit. Walk through Order Entry →
  • Separated Procurement. Prescribers approve; a procurement operator picks pharmacies in batch later. Enables clinical-shipping batching. View Procurement Queue →
  • Flat Order (PRD § 09). No durable Prescription. Described in comparison only — not recommended.

Clinic screens

  • 01Login Email + PIN. Shell only — no auth.
  • 02Dashboard Role-segmented widgets. Demo shows Prescriber; MA / ClinicAdmin / Ops variants called out.
  • 03Patients list Clinic-scoped patient table with filters.
  • 04Patient · Overview Identity, address, consent. Tabs for Prescriptions / Orders / Shipments / Clinical info.
  • 04bPatient · Prescriptions Durable Rx list. Each Rx → edit or "Create order from this Rx."
  • 04cPatient · Orders All orders ever placed for this patient (filter-locked Orders list).
  • 04dPatient · Shipments All shipments to this patient (filter-locked Shipments list).
  • 04ePatient · Clinical info Allergies / diseases / other medications. Three-state UI per section.
  • 04fWrite / edit Prescription The clinical authorization screen. Sign fires ID.me (per-Rx cadence).
  • 05Catalog list Read-only product list. Click through to product detail.
  • 05bCatalog detail One product: forms, strengths, pharmacy mappings, lead times.
  • 06Order Entry — basket flow Step 1 patient/ship-to → Step 2 add Rx lines (existing or new) → Step 3 pick eligible pharmacy → Step 4 review & submit.
  • 06bID.me step-up modal The per-Rx step-up — fires when signing a new prescription.
  • 07Order Detail Basket view: header + timeline + per-line accept/reject/shipment + sibling shipments.
  • 08Orders list Table with status pills. Click a row → Order Detail.
  • 09Refill Queue Rxs approaching exhaustion. One-click reorder reuses prior ID.me approval.
  • 10Profile Identity, MFA, clinic memberships. DEA + ID.me on Credentials.
  • 10bCredentials (sub-page) DEA license, state medical licenses, ID.me linkage.

Ops screens (HeroScript internal)

  • 11Network Order Monitor KPI tiles + network-wide order table with intervention actions.
  • 12DEA Verification Queue Pending DEA + state-license reviews. Click into User detail with Verify modal.
  • 13Invoices Daily settlement. Dual-context (clinic-scoped vs Ops global).
  • 14Audit Log Append-only event store. Actor, role, target, payload hash. 6-year retention.
